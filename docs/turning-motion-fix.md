# Turning Paths movement and sprite stability

The maze keeps its existing 1.35 zoom, layout, seed, clues and story progress. Camera easing previously left a visible tail behind movement, made more noticeable by the close view. The maze camera now follows the same current ground anchor used to draw Rae, with no easing debt. Terrain and actors share exactly the same projection in both phone orientations.

The terrain now lives in its own native SVG surface, under a translated/scaled native View. Its viewBox and contents stay fixed while the player moves within the cached region. The installed Android SvgView reuses its root bitmap when it is not invalidated. Actor movement and the sight tint update a separate foreground SVG, so they no longer invalidate the terrain painting on each stride. Region changes still update the nearby terrain; the game does not allocate a full-world native surface.

Rae and Tala now use persistent native atlases for both walking and common idle poses, including blinks, map handling and brief fidgets. Their image node, texture source and clipping definition stay mounted when a traveler stops or resumes. Speaking and special story poses still use the expressive vector artwork. There are 432 verified frame cells across the two atlases, each matching its authored source. Packing uses 16 columns so both textures remain below 2048 pixels on either axis. Rebuild with `node --experimental-strip-types scripts/prepare-traveler-atlas.ts`; the general mobile-art script also runs this preparation.

Regression checks exercise eye-closing intervals and repeated movement changes on Android/iOS boundaries; both retain the same image and clip instances throughout. Other checks validate each atlas cell, matching terrain/actor coordinates in portrait and landscape, a stable terrain surface while moving, and fresh joystick input published within a simulated 33.4 ms paint budget in all three trials. These are deterministic controller/rendering checks, not a physical-device input-latency or GPU benchmark.

Final validation: 174 tests, TypeScript checking, all three platform exports, and a live browser joystick/release check. The browser check keeps both travelers and the guide visible with the V1 materials and has no console warnings or errors. No physical phone is connected for a measured FPS result.
